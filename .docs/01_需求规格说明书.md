## 1. 产品目的

Embedded Helper是配合VS Code、EIDE和现有STM32模板使用的调试小助手。使用者选择嵌入式工程后，可通过GUI检查和维护调试配置，按需添加远程接入，在本地同页观察变量和原生RTT。远程变量在客户端查看，远程RTT沿用网页，首版二选一、手动切换。串口助手可独立使用。

目标使用组合为“VS Code + Embedded Helper”。VS Code 保持编辑、构建和源码调试的职责，小助手承担配置接入、运行数据可视化和串口通信。远程连接是可选能力，未接入 LAN-Debug-Server 时，本地连接及本地串口仍应可用。

首版入口为“打开工程”，不采用“开始调车”作为产品主流程。多设备调车场景的一键封装属于后续候选能力。

## 2. 背景与现状

截至2026-10-19，客户端基本可用，后续以现有功能打磨和待验收事项为主；以下区分当前实现与后续方向。

| 系统 | 当前职责与边界 |
| --- | --- |
| STM32-Template | 维护固件模板；原Debug_LAN工具的两个真实Release仍是客户端兼容下载来源，不能当作下载地址已迁移 |
| LAN_Debug | `client/`接管原Debug_LAN后续源码维护，`server/`维护Linux远程J-Link、网页RTT及串口TCP转发；不与Template并行维护同一工具源码 |
| Embedded Helper | C#/WPF/.NET 10客户端已实现工程/ELF解析、配置接入、工具选版、本地/远程变量SDK采集入口、本地原生RTT、独立串口及单EXE交付；软件验证证据见详细设计18节 |

客户端远程变量仍通过SDK直连远程J-Link，与服务端网页RTT手动互斥。LAN_Debug提出的r1唯一采集/保存、统一日志及标注接口是后续待讨论方向，尚未替换当前链路，也不是本轮必做项。服务端扫描、进程启动、日志清理等副作用仍需按实际源码核对，不能把查询入口一概当纯只读诊断。

## 3. 使用者与环境

### 3.1 使用者

- 嵌入式开发者：使用现有模板开发、烧录、源码调试和观察变量。
- 调试/测试人员：打开已有工程查看曲线、RTT，使用串口收发数据。
- 维护者：更新模板适配、工具接口和 Release，诊断兼容问题。

### 3.2 环境边界

- 客户端面向Windows x64，首批验证Windows 11 x64；其他Windows版本按测试结果单列，不从构建机版本推定支持范围。
- 本地 J-Link 通过 USB 连接；远程 J-Link 使用现有服务提供的 IP/端口。
- 远程服务运行于已有 Linux 设备；首版不以重写服务端为前提。
- 本地串口包括Windows COM设备及用户现有NRF串口链路；TCP远程串口暂不实现，后续有远端小电脑接串口的实际需求再评估。
- 用户仍需可用的 SEGGER 工具/库和对应硬件驱动。软件提供检查和定位能力，具体附带组件由发布方案确定。
- 产品日常使用无需安装Python、.NET运行时或SDK；自包含包携带必要运行时。Python只用于标准库开发Harness，已退出客户端产品路线。

## 4. 范围与优先级

| 优先级 | 功能范围 |
| --- | --- |
| P0：首版必需 | 打开现有模板工程；配置检查；可选远程接入；本地/远程变量可视化及本地原生RTT；远程变量与既有网页RTT手动切换；独立本地串口助手及双向有序记录；exe交付；单一源码来源与版本化工具依赖 |
| P1：首版后续增强 | Release在线检查/安装；统一记录与回放；高级变量类型 |
| P2：候选，不承诺首版 | 从模板 Release 新建工程；多板卡联合工作台；调车操作封装；参数组与自定义通信协议 |
| 当前不纳入 | 通用 IDE、CubeMX 替代品、任意 MCU 工程的自动迁移、已有业务工程的自动模板升级、完整源码调试器实现 |

P0 的 Release 依赖允许先通过离线发布包安装及手动选择版本完成闭环；在线获取和自动检查后续增量实现。工具实际运行不得依赖联网。

### 4.1 首批可用内测包

首批内测必须交付同一套可使用客户端，范围为G4工程识别、VS Code一键远程烧录配置及真实烧录链路、本地变量数值/曲线、本地原生RTT Up通道0、独立串口收发及双向记录、停止释放后手动恢复、布局/设置与诊断。用户无需手动复制Debug_LAN或编辑.vscode。一键配置不自动烧录，用户从生成的VS Code任务另行启动。

该批远程烧录入口为VS Code任务，EIDE原上传按钮切换仍保留为完整P0的可选接入需求；远程变量和网页RTT切换仍待硬件验收；其他模板配置样本与真实双版本工具Release的软件验证已完成，不能据此推定实机通过。内测发布用Pre-release，必须注明未完成项，不以局部通过宣称全部AC通过。

2026-10-11用户调整交付顺序：先离线开发，打包可启动、GUI正常的exe即可发布开发Pre-release，实机测试由用户后续完成。开发内测按AC-14，允许先交付已实现的完整操作页面并继续迭代；缺失功能须在界面和发布说明明确列出，不用空入口或模拟数据冒充。原AC-13保留为硬件验收完成的内测基线，正式Release仍需完整P0验收。

用户下载便携ZIP，解压到可写目录，双击EmbeddedHelper.exe；首次创建data，可无工程直接使用串口。打开G4工程后识别目标、ELF及配置来源，填写服务器/端口并应用接入，再从VS Code执行远程烧录；本地观察选择探针与变量后开始。SEGGER软件及设备驱动需外部安装，缺失时提供定位说明。升级保留data，工程状态继续位于原工程，不复制业务工程。

## 5. 功能需求

### 5.1 工程识别与配置

| 编号 | 需求 |
| --- | --- |
| PRJ-01 | 允许选择目录或工作区文件，定位实际工程根目录，识别模板系列、工程名、构建目标和已有配置。 |
| PRJ-02 | 首版一次使用一个工程和构建目标；存在多个候选时选择一次并记住。切换目标后重新推导ELF及连接配置，不提供多目标并行工作台。 |
| PRJ-03 | 模板目录可移动和改名；优先读取实际配置，固定目录仅作为有版本的适配规则。 |
| PRJ-04 | 显示每项配置的读取来源、解析结果和问题；未知模板或不兼容配置提供诊断，禁用不能可靠完成的写入。 |
| PRJ-05 | GUI 编辑的结果写入真实工程文件；后续 VS Code/EIDE 使用一致配置，而非仅保存于 GUI 内存。 |
| PRJ-06 | 修改一项逻辑配置时，计算受影响文件并一致更新，保留未知字段、用户已有任务和其他调试条目。 |
| PRJ-07 | 通过目录或工作区文件打开同一工程根目录时复用原配置，不创建项目副本；修改服务器写回现有remote-jlink.json；重复接入更新原管理条目。写入失败可恢复，写入前检测外部修改。 |
| PRJ-08 | 外部修改、ELF 重建、工程改名或模板规则变化后，可以重新检查和修复；修复结果需说明改变内容。 |
| PRJ-09 | 连接芯片型号与工程 MCU 配置分别识别和校验；编辑连接参数不自动改动 .ioc、启动文件或编译宏。 |
| PRJ-10 | 每个项目的数据保存在该项目目录：EIDE本地/远程上传配置保留在原工程文件，小助手状态保存在.embedded_helper。工程共享配置优先使用相对路径；本机工具路径和机器偏好放在软件目录下的data文件夹。 |
| PRJ-11 | 再次启动同一便携目录的软件，自动打开上次成功打开的工程并恢复有效目标；失效路径提示重新选择。恢复工程不自动连接设备、采集、烧录或调试。 |

首版支持 G4、H7、F4、F1 FreeRTOS 四类模板，F1 裸机不在首版范围。交付底线为 G4 完成配置与硬件链路测试，H7/F4/F1 FreeRTOS 完成适配移植和配置样本检查即可随版提供，不要求四类全部完成实机测试。界面和发布说明区分“G4已实测”“已移植、未实机验证”；配置写入能力按样本检查结果开放。

当前主导航为工程、MCU Viewer、RTT监视、串口助手、设置与诊断。工程维护目标/ELF及共享连接；变量选择、采样与绘图归MCU Viewer；本地和远程RTT归RTT监视。共享连接有效不代表设备已连接，变量/ELF问题只阻止变量功能。

### 5.2 本地与远程连接

| 编号 | 需求 |
| --- | --- |
| CON-01 | 默认支持本地 USB J-Link，远程 IP J-Link 为按需启用的连接配置。 |
| CON-02 | 记录本地探针选择和远程服务器/探针选择；切换后保留变量组、曲线布局和显示偏好。 |
| CON-03 | 切换可视化连接时释放旧连接；失败后显示真实状态，不自动改用另一探针。故障重试前必须清理旧连接，确认本产品旧工作进程已退出或旧SDK句柄已关闭，才能建立新连接。 |
| CON-04 | 可视化连接切换与工程烧录/源码调试方式切换独立。GUI 切到远程观察，不顺带把 EIDE 烧录器切到远程。 |
| CON-05 | 显示配置有效、网络可达、探针已连接、目标可读、有有效数据等不同状态。 |
| CON-06 | 采集与烧录/源码调试互斥。用户停止采集时释放探针，再启动外部工具；占用时提示停止另一工具并重试。首版不要求跨进程自动交接或探针租约系统。 |
| CON-07 | 源码调试结束后用户可点击开始恢复采集，保留观察列表和布局；无需自动判定所有外部工具的生命周期。恢复不主动擦除、烧录或复位 MCU。 |
| CON-08 | 串口连接具有独立生命周期；释放 J-Link 不应无条件关闭独立串口。 |
| CON-09 | 本地连接按工程记忆实体 J-Link：原选择在线则沿用；无历史且仅一个探针则自动选择；多个无法确定时显示型号/序列号供选择。原选择不在线时不自动改连其他探针。DLL 版本选择与实体探针选择分开。 |

### 5.3 一键远程接入

| 编号 | 需求 |
| --- | --- |
| REM-01 | 为已有工程一键添加或更新远程连接配置、VS Code远程烧录任务、LAN调试条目及配套工具引用；用户不手工复制Debug_LAN或编辑.vscode，重复接入更新原管理条目。 |
| REM-08 | 对支持的自家模板，从当前工程检测并一键导入所需 LAN_Debug 文件及配置，自动提取当前目标芯片/接口/速度；首次仅补充无法从工程得到的服务器地址等信息。工具准备在此流程内完成，不要求跨页或手动绑定本机 VS Code 环境变量。正常情况一次完成；冲突/未知模板时明确提示，失败恢复，不执行烧录或调试。 |
| REM-02 | 用户可选择是否同时接入 EIDE 远程烧录；仅添加 LAN 调试条目不修改本地烧录方式。 |
| REM-03 | 识别服务器、远程探针端口、本机 GDB 端口和串口端口的不同用途。 |
| REM-04 | 参数可在 GUI 中维护；保存后检查远程 JSON、launch、tasks 与所选 EIDE 目标的关联一致性。 |
| REM-05 | 添加远程方案后保留本地方案；“移除接入”指移除小助手添加的LAN任务/调试条目，并按记录恢复此前上传选择。接入记录随工程提交，跨电脑仍可识别；不删除业务文件或用户已有条目。 |
| REM-06 | 配置检查与真实连接检查分开；应用配置不自动开始烧录或源码调试。 |
| REM-07 | 接入遵循最小侵入原则：兼容已有remote-jlink.json、脚本参数和任务行为；打开工程不强制迁移旧入口。采用新工具入口时明确展示修改，旧工程和旧网页仍可独立使用。 |

已实现便利入口：通过系统默认浏览器打开现有服务网页，支持短主机名、完整主机名、IP、HTTP(S)地址及自定义端口。入口可独立使用，从项目打开时复用现有服务器配置；地址补全与保存规则见详细设计第11节。该候选不替代原生RTT需求，也不要求捆绑浏览器或重写网页。

### 5.4 变量可视化与 RTT

| 编号 | 需求 |
| --- | --- |
| VIS-01 | 调试主页采用变量列表、数值与曲线为主的布局，RTT 可停靠或展开。 |
| VIS-02 | 从所选 ELF 解析变量名称、地址和类型；首版覆盖固定地址的全局/静态标量变量。 |
| VIS-03 | 首版标量类型包括有符号/无符号 8、16、32 位整数和 float32；其他类型显示支持状态，不错误解释。 |
| VIS-04 | 可选择变量、添加/移除曲线、配置采样周期和保存布局；变量选择及有效频率编辑完成后自动保存到当前工程，失败就地提示并可重试或重新读取；长成员名优先保留末级字段，中间省略，悬停查看完整路径；统一与分道绘图均显示数值轴、刻度及时间轴（以实际读取时刻计秒，不按请求频率推算）。超过两个已添加变量时“分道独立缩放”置灰并切回统一坐标，悬停显示“仅显示少于2个参数”；两个及以下可重新选择分道。监测ELF文件修改时间，变化时仅提醒，提供“更新变量地址”操作，不强制停止采集或要求证明已经烧录。 |
| VIS-05 | 本地与远程变量使用相同页面和显示模型。远程变量与既有网页RTT首版二选一：停止当前消费者、释放探针后手动启动另一方；不要求同时采集或跨数据源时间对齐。 |
| VIS-06 | 变量读取不要求固件接入 RTT；RTT 面板仅在固件有对应 RTT 缓冲时提供数据。 |
| VIS-07 | 首版本地原生RTT支持Up通道0；远程RTT沿用既有网页，不开发远程原生面板或统一服务端采集接口。Down写入和更多通道按后端能力显示，不默认承诺可用。 |
| VIS-08 | 同一 RTT 通道只有一个实际消费方；展示、保存等功能订阅已读取的数据。 |
| VIS-09 | 采集与界面刷新独立；暂停画面和停止采集为不同操作；失效数值有“过期”标记。每次变量采集独立记录全部已接收批次，暂停显示仍记录，不受2000个显示点限制。停止后“保存调试数据”导出真实xlsx，包含时间、完整变量名、计划代次及缺失批次；超过Excel单表行数自动分表。空记录、写入失败和不完整记录明确提示，原始记录保留以便重试。 |
| VIS-10 | 显示请求/实际采样率、失败读取和数据缺口；轮询快照不得宣传为固件精确同步采样。 |
| VIS-11 | 工程 ELF 与目标固件的匹配状态可见；没有可靠核验方法时显示未核验。 |

首版不承诺任意表达式、栈局部变量、任意指针解引用和高速 HSS。固定地址结构体/定长数组成员展开按R-24实现并做软件逻辑验证；64位数值、HSS及目标缓存一致性仍待分别验证开放。

本地原生RTT为首版必需；远程网页由服务端Logger采集，客户端变量采集与它手动互斥使用。后续同时观察及关联时序另行评估；首版不为此要求固件增加时间戳或同步协议。主机接收时间不能证明MCU事件的精确时序。

### 5.5 独立串口助手

| 编号 | 需求 |
| --- | --- |
| SER-01 | 无需打开工程即可启动串口助手；参数和发送历史单独保存。 |
| SER-02 | 首版支持本地 COM，配置波特率、数据位、校验、停止位及适用的流控。 |
| SER-03 | 标准支持范围到 1000000 baud（1 Mbps）；允许手动输入 5000000，但明确标记为实验功能。拒绝、不支持和应用结果均有清楚反馈。 |
| SER-04 | 支持原始字节收发、文本/HEX显示、编码选择、换行选择、清屏及冻结当前并分栏。收发用两种颜色区分，正文不插入方向标记；文本跨块连续，半行即时显示。冻结时左侧持续更新、右侧保留独立快照，继续显示沿用实时侧历史，清屏只清实时侧；同次应用运行内重开串口不默认清历史。显示与快照有容量上限，裁剪可见。仅在上位机记录双向原始字节、方向、顺序和分段信息，时间戳可选。固件只需现有收发逻辑，不要求为记录新增时间戳或序号。上位机记录顺序表示本机观察顺序，不证明对端收到或跨方向物理发生顺序。 |
| SER-11 | 发送记录在显示区独占一行；实际末尾 LF 或 CRLF 显示为 `(LF)` / `(CRLF)`。显示分行不向串口追加字节，不修改原始记录；HEX 显示保留全部字节，接收仍连续解码，不以读取分块伪造行边界。 |
| SER-05 | 高速接收采用字节块处理，显示使用有界缓冲；原始接收不得依赖换行符。 |
| SER-06 | 显示收发字节数、速率、缓存积压、应用主动丢弃计数；保存与显示可独立进行。 |

## 6. 主要使用场景

### UC-01：打开本地工程观察变量

选择工程 → 识别目标及 ELF → 选择 USB 探针 → 连接 → 选择变量 → 采集。服务器不可用不影响本场景；连接配置和观察布局可恢复。

### UC-02：为工程接入远程能力

选择工程和构建目标 → 填写/选取服务器与探针 → 查看配置计划 → 应用 → 检查结果 → 按需在 VS Code/EIDE 启动调试或烧录。未选择远程烧录时维持原烧录方式。

### UC-03：切换可视化连接

本地采集中 → 切换远程 → 停止采集并释放本地探针 → 验证远程参数 → 连接并恢复相同观察布局。切换失败保留配置和历史数据，明确显示未连接。

### UC-04：独立串口测试

直接打开串口助手 → 选择设备和参数 → 以1 Mbps标准档持续收发/保存 → 查看吞吐和校验结果。需要时选择5 Mbps实验档开展公测，不要求 MCU 工程、J-Link 或远程服务器。

### UC-05：上游工具升级

上游发布新工具 → 小助手检查/离线导入 → 校验并安装至新版本目录 → 更新指定工程的版本选择 → 调用工具验证 → 可回退旧版。业务源码和连接配置不因工具升级被覆盖。

### 采集与解析环境（R-27）

按用途显示 J-Link 设备访问组件和 ELF 变量解析组件，完整路径收进详细设置。已指定路径优先且失效时不静默替换；仅一个有效候选可填入待保存路径，多个候选由用户按来源/版本选择。查找仅检查工程 .vscode/settings.json、launch.json、remote-jlink.json 中明确的工具路径，VS Code 用户设置、EIDE 默认目录、SEGGER 安装目录和 PATH；不运行配置命令、不全盘搜索，不宣称识别所有 EIDE 自定义格式。支持 userHome/workspaceFolder 和环境变量路径；未解析变量给出提示。J-Link 静态校验64位PE及所需导出接口，不加载库或连接设备；readelf校验Windows可执行文件，实际解析在打开ELF时验证。文件通过不等于依赖加载/实机可用。保留手动指定，保存时拒绝非空无效路径。
