## 1. 设计约定

本文件细化首版所需的数据模型、模块契约、处理流程和验证方法。示例中的新文件、CLI参数、进程协议及Release元数据是目标接口，当前实现与验证边界集中见18.4～18节，不能以设计示例认定已完成。

本文维护当前数据模型、接口、算法与验收方法；目标契约不等于全部已实现。客户端采用C#/WPF/.NET 10 LTS，现有证据与未验边界集中于18节。Python产品原型已归档至Git基线a7f30e11a86b8a60f15f853202da19bfba99a4c4，不作为当前执行入口。

首版采用Viewer式操作：开始读取变量，停止后释放探针，再使用源码调试；观察不主动发送复位/停核/烧录命令。连接行为在G4测试时记录，无需用户为“可能短暂停核”预先选择策略或逐次确认。若实际出现目标停住或重启，应作为具体连接问题排查，不把它设为正常采样流程。显式烧录、源码调试继续遵循原工具流程。

### 2.2 工程内与便携软件目录

工程内拟新增：

~~~text
.embedded_helper/
  project.json       工程适配、构建目标、观察引用及布局
  tools.lock.json    工具版本及已确认的发布包校验信息
  integration.json   产品条目归属、接入前上传选择及接入后的字段值
~~~

继续使用原文件：

~~~text
Debug_LAN/remote-jlink.json
.vscode/launch.json
.vscode/tasks.json
.eide/eide.yml
*.code-workspace
CubeMX/*.ioc
~~~

实际工程层级由适配器识别，不假定Debug_LAN始终位于所选工作区根目录。文件不存在与内容不兼容分别报告。

软件采用便携目录布局，以外层exe所在的软件目录为基准创建data文件夹，不依赖启动时的当前工作目录。工具缓存位于data/tools；本机设置、串口参数及发送历史沿用data/settings/window.json，原始串口记录位于data/serial/records；运行日志位于data/logs；短期备份与事务日志位于data/projects/<工程标识>/transactions。该标识由规范化项目绝对路径生成，并同时保存原路径供诊断。软件目录不可写时明确提示移动到可写目录，不静默改存其他位置。升级替换程序文件时保留data。

SettingsStore保持既有window.json字段名及默认值，拆分代码不迁移或双写文件；缺失字段采用模型默认值，无效JSON报告错误并保留原文件。观察配置为工程内.embedded_helper/watch.json，由WatchSettingsStore统一读写，包含Target、Identities、Rate；R-07追加Transport（local/remote）、ProbeSerial与EnableRtt，不保存运行读数或绝对ELF路径。旧文件默认local、空序列号、RTT开启；保留目标/变量/采样率，但需要用户在工程观察设置中补齐探针并显式保存。window.json旧Probe字段仅为兼容保留，不再借用或更新为工程采集参数。窗口保留刷新、操作转发及WPF关闭入口，各页View通过类型明确的事件通知展示层；ObservationViewModel维护查看状态，Core中的ObservationPreparation产生完整准备结果，ObservationCoordinator及SerialController分别持有观察与串口生命周期，页面重建不创建新会话。详见概要7.7及本文件18节。

项目与本机设置的归属遵循PRJ-10及概要6.1。工程内保存相对路径和可共享配置，不新增队员电脑的绝对安装路径、COM号或运行中状态；旧配置中的机器路径按3.3兼容处理。移动便携目录后重新校验本机工具路径和稳定CLI入口绑定。

.embedded_helper默认可提交仓库，不自动加入.gitignore。integration.json只保存管理条目的语义位置、原字段是否存在及原值、写入后的值、目标身份和相对路径；不复制整份工程或原始日志。原上传配置若包含机器路径，保存为需要本机重新绑定的恢复提示，避免共享另一台电脑的绝对路径。

## 3. 标准化工程模型

### 3.1 只读识别结果

| 字段 | 含义与来源 |
| --- | --- |
| projectRoot | 本次选择并确认的工程根目录 |
| adapterId / adapterRevision | 匹配的模板规则及修订号 |
| templateFamily / templateVersionEvidence | 系列与版本证据；无法识别时标记未知 |
| buildTargets / selectedTarget | EIDE中的目标集合及用户选择 |
| deviceIdentifiers | IOC、EIDE、J-Link配置等各自名称及来源 |
| artifactCandidates | 根据所选目标推导的ELF/HEX等候选产物 |
| remoteConfigPath | 已存在或拟创建的远程配置路径 |
| capabilities | 可读取、可修改、可接入、可撤销等逐项能力 |
| diagnostics | 冲突、缺失、过期产物、规则不匹配及来源 |
| fileSnapshots | 各输入文件的原始字节、内容摘要与编码信息 |

识别顺序：读取工作区和目录结构 → 读取EIDE目标 → 关联IOC和产物 → 匹配适配规则 → 检查字段来源及冲突。多工程、多IOC或多构建目标不得自动取第一项；保留候选并由用户选择。

以识别后的实际工程根目录复用项目：通过目录或工作区文件选择到同一根目录时，读回原项目配置，最近项目入口去重，不复制工程或生成第二份配置。更改服务器地址更新该项目现有remote-jlink.json；软件data中的最近记录仅引用项目位置，不成为项目配置的第二权威来源。

芯片名称可能存在STM32G474VETx与STM32G474VE等不同写法。适配器只使用已验证的映射表，不通过随意截断字符串猜测J-Link设备名。

### 3.2 拟新增project.json

以下示例以G4、Debug目标为说明，实际路径由识别结果生成。address/type等采集地址不作为长期权威配置保存；每次根据当前ELF重新解析。

~~~json
{
  "schemaVersion": 1,
  "adapter": {
    "id": "stm32-template",
    "family": "g4",
    "revision": 1
  },
  "buildTarget": "Debug",
  "artifacts": {
    "elf": {
      "mode": "derived"
    }
  },
  "observation": {
    "preferredTransport": "local",
    "remoteConfig": "Debug_LAN/remote-jlink.json",
    "requestedSampleRateHz": 100,
    "watchList": [
      {
        "symbol": "motor_speed",
        "symbolIdentity": { "name": "motor_speed", "linkage": "global" },
        "display": "curve"
      }
    ],
    "rtt": {
      "enabled": true,
      "upChannel": 0,
      "textEncoding": "utf-8"
    }
  },
  "integration": {
    "remoteDebug": false,
    "remoteFlash": false
  },
  "toolLock": "tools.lock.json",
  "extensions": {}
}
~~~

约束：schemaVersion不支持时只读；采样率是请求值，实际值另行统计；ELF允许显式相对路径覆盖，覆盖必须展示来源；integration字段表达小助手管理的接入意图，启动时仍校验真实任务和上传配置，不能仅凭布尔值认定已经接入。同名静态变量的symbolIdentity另存编译单元和作用域，避免只靠短名匹配。

首版只保存一个当前buildTarget和一套观察布局。切换目标时重新推导产物和连接参数，清除上次运行的读计划；按符号身份重新解析观察项，缺失项标无效。不自动把旧目标的显式ELF覆盖用于新目标，不建设多目标独立配置工作台。

ELF覆盖及remoteConfig相对于工程根目录，toolLock相对于project.json所在目录。所有路径在规范化后检查边界；明确记录基准，不依赖程序当前工作目录。

本地连接原型以选定EIDE目标的uploadConfigMap.JLink.cpuInfo.cpuName和speed为来源，与唯一J-Link launch的device/interface交叉核对。EIDE3.27.2的proType枚举0=JTAG、1=SWD；冲突、缺失或多候选时拒绝自动选择。MCU deviceName独立展示，不用截断方式推导连接芯片。当前只读，不创建remote-jlink.json，不开放未验证覆盖写入。

按2026-10-12用户确认，当前本地探针选择随工程观察设置存入watch.json的ProbeSerial；软件安装路径仍属本机设置，旧window.json中的Probe只兼容保留，不用作采集输入。远程服务器和端口来自工程remote-jlink.json，不在watch.json重复维护。观察模式变化只改工程观察设置；工程烧录/调试配置变化由独立接入用例处理。

### 3.3 现有remote-jlink.json兼容

现有字段保持：

~~~json
{
  "ServerName": "robocon-r1-debug.local",
  "Port": 19011,
  "Device": "STM32G474VE",
  "Interface": "SWD",
  "SpeedKHz": 8000,
  "JLinkExe": ""
}
~~~

ServerName接受主机名或IP，Port为1～65535；Interface按照实际工具支持校验；SpeedKHz为请求速度并遵守工具及硬件限制。JLinkExe空值沿用工具查找规则，非空机器绝对路径提示属于本机设置并提供迁移选择。

Remote Server端口与本机GDB Server端口是两个独立字段，不能将19011与2331互换。GDB相关端口还要检查相邻SWO/Telnet端口占用和范围。

## 4. 模板适配器接口

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| probe | 目录与只读快照 | 匹配证据、歧义、能力 |
| read | 选定目标与快照 | 标准化工程模型 |
| validate | 工程模型与运行环境 | 字段级诊断 |
| planIntegration | 编辑草稿、目标、接入选项 | 文件级变更计划 |
| validateWritten | 写入后的快照 | 真实配置一致性结果 |
| planRemoval | 当前快照、原接入记录 | 可撤销条目与冲突 |

能力按系列和操作标记，支持范围和开放条件遵循需求5.1及AC-01、AC-09；样本通过与实机通过分别记录。

配置页使用适配器生成的字段描述：显示名称、类型、当前值、来源文件、校验规则、只读原因、影响文件集合。界面绑定字段描述，不硬编码某一模板的YAML路径。

| GUI修改 | 预期影响 | 限制 |
| --- | --- | --- |
| 服务器/远程端口 | remote-jlink.json及引用检查 | 不影响本地观察端点 |
| 接口/速度 | 所选连接配置、有关启动参数 | 不改MCU时钟或固件 |
| ELF引用 | 观察引用及管理的调试配置 | 依据构建目标校验；不移动产物 |
| 本机GDB端口 | 管理的LAN任务与external调试配置 | 检查相关端口一致性 |
| 添加LAN调试 | 产品管理的tasks/launch条目 | 保留用户本地调试条目 |
| 添加远程烧录 | 所选EIDE目标上传配置及工具引用 | Custom CLI结构经真实版本验证后才能写入 |
| 更换MCU | 诊断及重新识别 | 首版不修改IOC、芯片宏或自动生成源码 |
| 切换观察本地/远程 | 小助手观察偏好与会话 | 不切换EIDE上传方式 |

产品管理条目用.embedded_helper/integration.json中的相对文件路径、JSON/YAML语义位置、唯一条目标识及前后字段值追踪。其更新纳入同一次配置事务；用户改名或删除后重新匹配，不能仅按相同显示名称覆盖任意条目。另一电脑可读取该记录，无需原机器备份。

再次应用同一项目的接入设置时更新已有管理条目，不创建第二个项目或追加同名条目。首次接入前的上传选择作为移除时的恢复依据保留；后续修改服务器等参数仅更新当前配置和管理条目的写入后值。若用户另行修改上传方式，则按当前值与归属记录判定冲突，不用旧记录覆盖用户修改。这是内部恢复规则，不新增日常确认步骤。

读取JSONC采用支持注释和位置的解析方式，修改局部节点；YAML使用能保留注释、顺序和未知字段的往返方案。具体库随语言确定，需以真实样本验证。无法无损表达的文件进入只读/人工处理，不降级为整文件模板覆盖。

首批一键接入只自动准备已发布工具/稳定入口引用、remote-jlink.json及产品管理的.vscode任务/调试条目，不开放通用配置编辑器。填写服务器/探针端口、检查芯片/ELF来源、点击应用即可完成，重复执行更新原条目；真实远程烧录由用户在VS Code任务启动。已有Debug_LAN不无条件覆盖，源码不复制到本仓维护。EIDE上传按钮写入留待独立实测；.vscode往返、用户任务保留、外部编辑与失败恢复须在C#重新验证。

## 5. 配置计划、写入与撤销

### 5.1 变更计划模型

每个Plan包含planId、工程和目标、适配器版本、预期原文件摘要、语义修改、完整预期输出、变更摘要、校验结果和恢复信息。用户看到文件清单及功能变化，可展开文本差异。

应用前拒绝：字段校验失败、写出路径越出已确认工程边界、输入发生变化、未验证的适配器写入能力、磁盘不可写、目标文件无法安全保存。配置路径中的符号链接/目录联接需解析并核对实际目标。

### 5.2 多文件写入流程

1. 获取本产品的工程写入锁；重新读取输入文件并比较摘要。
2. 保存原始字节和新文件不存在的事实；生成事务日志prepared。
3. 将新内容写入目标文件同目录的临时文件，关闭文件并校验可解析性及内容摘要。
4. 按计划逐个替换，每步记录已修改文件和结果；单文件采用平台提供的替换方式。
5. 全部写完后重新解析，验证端口、路径、目标与产品条目之间的一致性。
6. 成功记录committed；失败尝试恢复未被外部再次修改的文件并记录结果。

多文件操作没有天然整体原子性，日志用于失败和崩溃恢复。本产品的锁不能阻止VS Code、EIDE或其他进程写文件；应用前和每个替换步骤均检查当前摘要，应用后再次检查。外部并发仍可能形成冲突窗口，不能宣称消除了所有竞争。

若回滚时当前文件不是本事务写出的内容，停止覆盖该文件，保留备份和冲突信息，显示“需要处理”。不为恢复而覆盖用户的新编辑。

### 5.3 崩溃恢复和撤销

启动识别未完成的事务：根据每个文件的原摘要/新摘要/当前摘要判定未写入、已写入、已恢复或外部变化，生成恢复计划。只有内容身份可确认的文件才自动恢复；其他文件提供差异与备份路径。

“移除接入”指撤掉本产品添加的LAN任务/调试条目，并恢复该目标原上传选择，不是删除.embedded_helper或让配置退出Git管理。根据integration.json中的原值、接入后值和当前值比较，只修改可确认归属的字段；不把整份旧备份覆盖到当前工程。记录缺失或用户后续修改产生歧义时展示差异供手动处理，不阻止继续使用本地工程。

备份有保留策略和清理入口。配置正常打开、观察切换、串口使用不创建工程写入事务。

## 6. 稳定CLI与现有工具衔接

### 6.1 现有工具边界

当前Debug_LAN/jlink_flash.py具有--config、--program、--gdb-server、--gdb-port、--jlink-path、--dry-run等参数，GDB后台启动输出包含“[remote-jlink] GDB STARTING”和“[remote-jlink] GDB READY”。现有任务利用就绪输出组织源码调试。

现有烧录流程会调用reset/halt/load/reset/go等命令。小助手仅配置接入时不得顺带调用烧录；观察操作不能借用烧录脚本建立连接。

新工具Release应优先保持上述参数语义和就绪输出。稳定入口负责定位版本、读取配置、结构化启动工具和转发输出，不复制Commander/GDB Server内部逻辑。用户先停止采集再调用烧录/调试，首版不做自动占用交接。

兼容验证以旧工程真实样本为准：旧脚本读取新客户端保存的remote-jlink.json、新入口读取旧配置、未迁移的旧tasks/launch继续调用原脚本，以及服务网页导出的配置仍能供工程使用。仅打开工程不得删除原Debug_LAN脚本、迁移任务或强制升级服务端。工具包统一分发针对新接入和显式迁移，不要求清除旧项目中已存在的脚本。确需停止支持旧协议时，记录支持版本、迁移办法并同步修改调用方与上游，兼容验证后再移除旧入口。

### 6.2 稳定入口契约

~~~text
EmbeddedHelper.exe --cli --version
EmbeddedHelper.exe --cli --project <工程目录> flash --program <产物>
EmbeddedHelper.exe --cli --project <工程目录> gdb-server --gdb-port <本机端口>
EmbeddedHelper.exe --cli --project <工程目录> check
~~~

上述为外部命令，启动器转入CLI后按tools.lock定位工具，再映射现有--config/--program等参数；工具包后续扩展接口以cliApiMajor控制兼容。

VS Code/EIDE通过本机EMBEDDED_HELPER_ENTRY调用外层EmbeddedHelper.exe --cli，升级只替换外层EXE即可选择当前组件；开发多文件布局可绑定内部CLI，其同样接受--cli前缀。RuntimePaths集中定义HomeDirectory（软件目录）、ComponentDirectory（当前组件目录）和DataDirectory（软件目录/data），Worker始终由当前组件目录启动；CLI显式--data仍覆盖数据目录。便携启动器将自己的实际路径传给子进程，支持EXE改名；组件独立启动时默认外层名EmbeddedHelper.exe。移动目录后须重新绑定并重启VS Code。

旧EMBEDDED_HELPER_HOME保持不变，避免破坏尚未迁移的工程。旧VS Code/EIDE命令通过接入预览及ConfigTransaction更新；integration.json记录的旧内容必须仍与磁盘一致，外部修改拒绝覆盖，移除仍恢复接入前EIDE字段。全部旧工程迁移之前保留原组件目录；旧绑定不会自动获得升级后的CLI。工程内不记录本机绝对入口路径。

GUI关闭时CLI仍可运行；CLI管理自己启动的工具进程，不能因GUI关闭结束独立GDB会话。取消后按所启动进程身份清理自己的子进程，不按名称结束全部J-Link进程。不为此引入常驻协调器。

参数通过进程API的参数数组传递，路径单独处理。就绪日志、标准错误、退出码和取消状态分别记录。已知超时错误即使工具退出码为0，也不能显示烧录/调试成功。

外层错误至少区分配置无效、版本缺失/不兼容、端点占用、连接失败、工具失败和取消；数值退出码在工具API正式定义时统一。原始工具退出码单独保留，避免与外层含义混淆。

check仅做配置与环境检查；涉及网络、工具启动和目标连接的检查明确分级。现有--dry-run可能解析主机和查找程序，不等于完全离线，也不作为配置写入成功的唯一依据。

## 7. 会话协调与SDK工作进程

### 7.1 端点模型与占用

端点具有transport、localProbeSerial或remoteHost/remotePort、device、interface、requestedSpeedKHz。显示服务器主机名与解析后的地址，避免解析变化被隐去。

首版一个采集工作进程对应一个探针，GUI只管理自己的连接。用户停止采集后关闭SDK句柄，随后使用VS Code/EIDE；结束调试后手动开始采集。占用导致连接失败时显示原始错误和操作提示，不实现命名管道协调器或租约系统。

端点记录所选序列号或主机/端口即可，首版不建立跨电脑物理身份归并数据库。更换端点前关闭当前连接，不自动选择另一探针。

网页RTT和其他工具由用户停止；连接失败可直接重试，无需额外“确认释放”审批。客户端不自动结束外部进程。

### 7.2 状态与转换

~~~mermaid
stateDiagram-v2
    [*] --> Disconnected
    Disconnected --> Connecting: 用户连接
    Connecting --> Sampling: SDK连接并开始读取
    Connecting --> Fault: 失败或超时
    Sampling --> Stopping: 用户停止或切换端点
    Stopping --> Disconnected: SDK关闭并释放探针
    Stopping --> Fault: 关闭超时
    Sampling --> Fault: 断线或工作进程失败
    Fault --> Stopping: 用户重试，先清理旧连接
    Fault --> Disconnected: 已确认完成清理
~~~

每个会话有generation。切换端点、用户更新变量地址和工作进程重启会提升generation；迟到的旧代事件不混入新曲线。单纯检测到ELF时间变化只提醒，不提升代次或停止采集。

### 7.3 SDK调用隔离

工作进程拥有唯一J-Link句柄，同一时刻只执行一个SDK调用。命令包含requestId、generation、操作、参数和截止时间；控制响应与数据流分开。

优先级建议：停止 → 连接检查 → 变量读取和RTT按预算轮转 → 低频状态。RTT不能持续占满队列；变量读取也不能让RTT长期饥饿。

SDK阻塞超时不能靠UI线程取消。工作进程先尝试正常关闭，超时后由应用结束自己的工作进程，并等待确认退出。故障后重试必须先完成旧连接清理：旧SDK句柄已关闭，或持有它的旧工作进程已退出，才能从Disconnected进入Connecting；清理失败保持故障状态并说明原因，不并行创建新连接。清理完成后可继续用户已请求的重试，无需再次确认。结束进程不隐含复位目标或终止外部调试器。

P0不默认提供变量写入、寄存器编辑或自动复位。SEGGER DLL寻找、位数匹配、错误码和发布方式属于独立验证项；不得将PyLink可导入当作官方库已安装。

## 8. ELF索引与变量读取

### 8.1 索引流程

读取ELF头和段信息 → 检查目标架构/字节序 → 建立符号和DWARF类型索引 → 解析用户观察项 → 生成受限读计划。

首版支持具有固定存储地址的全局/静态整型及float32；8/16/32位有符号与无符号整型须按实际类型解释。优化导致不存在、DWARF复杂位置表达式、局部栈变量、TLS、动态指针和未知类型给出不支持原因。

同名静态变量使用编译单元/作用域身份区分，不只用短变量名持久化。已显示地址不作为永久定位依据。

结构、数组展开、64位值、指针追踪、HSS和特殊存储区访问分别列为能力扩展。某些32位MCU的多字节值可能非原子更新；连续读取或一次批量读取都不能保证跨变量的同一时刻快照。

### 8.2 固件与ELF关系

文件修改时间用于低成本检测ELF更新；采用“不等于上次时间”而非仅“大于”，避免回退旧文件漏提醒。该时间是文件系统修改时间，不是烧录时间。解析缓存可用内容摘要和解析器版本校验，不把摘要核验做成用户操作门槛。

目标未提供可核对的固件身份时显示“ELF与目标固件未核验”。后续可利用双方实际支持的build ID或约定固件标识建立核验流程；不能仅凭芯片相同就认定匹配。

ELF变化后显示“ELF已更新，请确认已烧录并更新变量地址”，默认继续当前内存中的读计划，不自动替换地址或强制暂停。提供“更新变量地址”按钮；点击后解析文件并在批次边界切换读计划，缺失项标无效。重启后没有旧计划时解析当前ELF，保留未核验提示，允许开始。文件暂时不可读时提示重试，不把半写入文件当新计划。以后可增加自动刷新/变化时停止选项，首版无需实现。

同一打开项目会话内，停止再开始和本地/远程端点切换只提升会话代次，保留当前内存读计划；不借重连自动解析新地址。用户更新成功才原子替换计划，解析失败保留旧计划。关闭后重新打开项目或切换构建目标时重新解析当前ELF，继续显示固件未核验。

C#解析候选LibObjectFile需通过自有样本与真实G4产物的DWARF版本、优化设置、类型别名和静态变量重名测试。只用ELF符号长度不能区分float32与int32；不支持的位置或类型明确报告，不猜测解码。固定CU/DIE偏移不是跨重编译身份。

外部烧录/调试按停止—外部操作—开始的流程处理；重新连接时重新定位RTT。H7缓存相关读数问题作为该系列公测记录，不阻塞G4交付，不预先建设完整缓存一致性方案。

### 8.3 读取计划

每项保存symbolIdentity、address、byteLength、typeDescriptor与requestedRate。首版只按ELF固定地址变量的实际长度逐项读取，检查类型宽度、地址溢出和读取返回结果；不扫描任意地址，不合并相邻变量。safeMemoryRegion并非逐项读取必需字段，暂不引入；以后做批量合并时再依据芯片内存图限定边界。读取失败只使对应值无效，不伪造0值。

调度按单次最大读量、每轮时间预算和公平轮转执行。请求100Hz但实际只有70Hz时显示实际采样率、读取耗时和缺口，不重复旧值伪造100Hz。

时间戳同时保存主机单调时钟的读取起止和墙上时间。没有目标端时间戳时，只代表主机观测时间，不能当作MCU内部事件的精确发生时间。

## 9. RTT、事件与显示

### 9.1 RTT通道

每个RTT上行通道在采集会话中只有一个读取者，读取后向显示/记录分发。rtt_start、定位、通道检查和读取错误分别记录；无数据不等于断线。

本节仅描述本地原生RTT；远程沿用网页，与客户端变量采集手动互斥。首版支持上行通道0，支持原始字节与增量文本解码，更多通道不默认开放。通道不存在、固件没有RTT控制块或尚未输出应给出不同状态。RTT下行发送可列P1，需专门定义写入、容量、流控和失败反馈。

清屏只清界面历史，重启采集不默认清目标buffer。RTT缓冲区本身的阻塞/丢弃策略由固件决定，客户端不能承诺不存在目标端丢包。

### 9.2 事件协议

所有事件至少有sessionId、generation、sequence、kind及payload。变量批量事件附主机读取起止时间、计划版本和值质量；RTT和串口事件附来源、通道、字节偏移与原始字节；串口记录的时间字段可省略，以序号维持顺序。状态事件附原因及原始错误。内部性能统计可使用主机时钟，不要求设备端生成时间戳。

控制面可以使用JSON；高频字节流优先采用有长度上限的二进制帧并分块传输，避免逐字节/逐变量序列化。具体编码随实现确定，但帧长度、版本、流ID和序号必须有校验。

低频状态/错误使用独立通道或保留容量。高频数据队列满时按照策略合并显示数据或标记丢弃，不能静默丢失断线/失败事件。

### 9.3 有界缓冲与绘图

变量曲线、RTT显示和串口显示分别设置时间/容量窗口。曲线按当前像素宽度抽取极值等显示点，原始数值不因显示抽稀被伪装为全部保留。

界面刷新独立限频，候选20～30次/秒，实施时测量。过期值显示更新时间和状态；NaN、Infinity及读失败不强制转成0。切换端点用时间线边界区分新来源。

当前WPF绘图采用独立ObservationPlot和StreamGeometry，UI线程维护有界历史、向控件提交批量快照，按像素桶保留极值并缓存几何；无新数据/尺寸变化不重复建图，隐藏页跳过渲染。ScottPlot仍是后续有测量依据时的候选，20～30Hz刷新和真实时间轴尚未实施。30分钟内存/响应仍须另行验证。

暂停显示只冻结画面，后台采集和已启用记录继续；停止采集才停止硬件读取。恢复显示时按历史窗口规则展示，裁剪和缺口仍保留标记。

原始记录可选，写盘队列独立于显示队列。磁盘慢/满时报告记录失败或缺口；不能因为界面仍流畅就声明原始数据完整。首版串口的原始保存需验收，统一会话回放列P1。

## 10. 独立串口助手

### 10.1 设置模型

| 参数 | 规则 |
| --- | --- |
| port | 本机枚举与手动选择，不依赖J-Link探针列表 |
| baudRate | 正整数自定义输入，标准范围到1000000；5000000标记实验档 |
| dataBits/parity/stopBits | 根据实际驱动能力设置和反馈 |
| flowControl | 明确无/硬件/软件流控，默认值可见 |
| displayMode | 文本/HEX；文本编码可选并增量解码 |
| sendMode | 文本/HEX、手动/周期；周期和取消有明确状态 |
| recording | 双向原始字节、方向、序号、分段索引；时间可选；输出路径、容量/分段及失败状态，详见10.4 |
| rs485Mode | 无/硬件自动换向/经验证的驱动模式，能力可见 |

打开端口、设置参数、驱动接受、开始接收是不同状态。库能设置5000000只说明配置请求可能被接受，不能证明线路实际达到5Mbps或零误码。

### 10.2 收发与背压

显示模型保留不可变的`SerialTextSpan(Start, Direction, Text)`，而非将方向前缀写入正文。文本按TX/RX独立增量解码，半行即时可见；HEX也不以接收块边界强制换行。相邻同方向片段在1024字符内合并，实时窗口最多65536字符、4096片段，先达到的上限触发头部裁剪；裁剪不截断UTF-16代理对。冻结快照只引用不可变片段，实时追加、裁剪、清屏或切换编码不修改快照。清屏只清显示，保留正在解码的半个字符；新会话重置解码器而保留已显示历史。所有处理仅影响显示，`OrderedRecorder`的原始记录格式和字节保持独立。

WPF显示使用SerialLogView与独立的FlowDocument/Run，收发颜色来自SerialRxBrush、SerialTxBrush。保留原有100ms刷新、每次最多256块或8ms的队列读取预算；按绝对字符偏移增量追加、头部裁剪并恢复仍在缓存中的阅读锚点及选区。富文本不引入额外换行，复制拦截器仅提取选中Run的正文，排除文档末尾的隐式段落换行。读取预算不包含布局时间，响应及内存需以真实WPF测量结果评估。

冻结时两栏初始各占一半，GridSplitter可拖动，最小宽度各120；右侧保留当前模式、选区及阅读位置，左侧恢复跟随。继续显示隐藏并释放右侧文档，保留左侧内容、位置及跟随状态。清屏以当前会话PublishedSequence标记边界，旧排队块继续参与解码但不再显示；切换编码/HEX时旧排队块直接跳过，避免污染新解码器，右侧快照不变。关闭会话先等待生产者退出，再分批排出已接受的显示尾部；打开失败也不得清空历史。历史超过容量时明确提示，退出应用不自动恢复显示历史。

周期发送状态为Idle/Running/Stopping/Stopped/Faulted，界面持续显示周期与驱动已接受次数；取消先进入Stopping，等待当前发送结束后进入Stopped，故障保留原始异常。HEX解析在发送之前拒绝非十六进制字符或不完整字节，界面给出中文说明，异常详情写入诊断日志；不将驱动接受描述为对端送达。

工程ELF解析成功后重新计算文件诊断，保留其他目标及配置告警。观察准备失败可携带已验证的当前目标WatchSettings与已完成的ELF索引；查看页据此显示保存的身份和数量，索引未完成时地址、类型明确标为未解析，不能借用旧目标的地址。缺远程配置或SDK仍禁用开始采集，RTT空状态依据保存设置显示，准备过程不启动Worker或加载SDK。

接收使用原始字节块，适当短超时或事件通知，禁止依赖换行结束。转发、显示解码和保存各自消费已接收数据，不在接收线程逐字符更新控件。

以8N1计算，1 Mbps标准档每方向约100kB/s，5 Mbps实验档每方向约500kB/s；内部缓冲可按实验档预算，首版验收使用1 Mbps。半双工RS485不保证同时双向达到该速率；测试记录帧间隔、换向及有效负载比例。

初始环形缓冲可从8MiB和有限分块开始试验；该值是测量起点，不能替代长时间压力测试。队列按字节容量计量，记录最高占用、显示裁剪、原始丢弃和写盘延迟。

发送队列同样有界；周期发送不得无限积压。“已排队”“驱动已接收”和“对端已确认”分开。取消周期发送停止新数据进入队列，剩余队列是排空还是取消由明确操作决定。

C#串口使用System.IO.Ports，DataReceived仅作通知，不按事件次数或换行计量原始字节。Write接口不返回实际部分写入长度，超时/失败时若无法确定已发送量须记录结果不确定，不把整块标为已送达或盲目重发；若验收要求精确驱动进度，增加经测试的Windows原生适配。已有Python软件回环不能证明该实现可用。

### 10.3 RS485与错误统计

优先使用转接器硬件自动DE或可验证的驱动支持。通用桌面线程/定时器无法承诺微秒级换向；不将用户设定延迟直接宣传为实际线路时序。

统计包括接收/发送字节率、帧率（有协议时）、队列、水位、记录速度和可获取的驱动错误。驱动无法报告校验/帧/溢出错误时显示“不支持”，不显示0误码。

误码/丢帧验证使用测试对端提供的序号、长度、校验或已知字节模式。1 Mbps标准验收按需求AC-06进行，5 Mbps单列公测报告；仅收到可读文本不等于完整性通过。线缆长度、终端电阻（RS485适用）、收发器、转接器型号和驱动版本一起记录。

拔插后停止当前会话并显示原因；不自动把另一个COM号当作原设备。根据稳定设备身份和用户选择重连。

### 10.4 双向记录

按SER-04仅在上位机记录TX/RX两个方向，显示编码与HEX模式不改变原始字节。每条记录包含sessionId、sequence、direction、字节长度及原始内容；记录入口串行分配会话内递增序号，两个方向共享序号空间，每个方向保持原有字节顺序。固件无需新增时间戳、序号或日志协议。

序号表示上位机记录入口观察到的顺序；主机并发收发、驱动及链路缓存可能影响观察顺序，不能据此还原远端跨方向的物理因果关系。主机时间戳可选：如保存，RX表示主机收到字节块的时间，TX表示驱动写入结果的观测时间，不表示对端已确认。部分写入只记录实际接受的字节数，失败和未发送部分另记状态。

分段元数据至少包括会话ID、段序号、首末记录序号、文件名及结束原因，起止时间可选。切段不重置会话序号；分段容量默认值由实现测量确定，异常结束保留未完成标记。记录队列丢弃需保留缺口范围；写盘失败、队列丢弃与显示裁剪分别统计。文件编码与容器格式由实现选型，不增加首版回放界面。

AC-06需在无时间戳的记录中核对双向字节、方向、序号及段间连续性；TX端是否真正送达由专用测试对端的已知数据/校验验证，不向业务固件增加记录要求。NRF在电脑端按普通COM收发，不增加专用解码或TCP转换层。记录序号能发现上位机已知的记录缺口，不能单独发现进入主机前的无线丢包。

## 11. LAN-Debug-Server增量适配

首版用户可手动填服务器与探针端口，直接使用现有J-Link Remote Server。服务端发现、RTT交接和远程串口控制不作为本地场景的前置条件。

现有服务的/get_jlink_list可能扫描并保存设备状态，/start_rtt会改变配置和启动进程；部分GET并非纯读取。适配前只读核对源码，不通过导入app.py或盲目请求来“检测环境”。

已核对app.py的/start_rtt与JRTTClient.py：网页RTT由服务端JLinkRTTLoggerExe采集，使用设备型号、接口、速度、远程探针端口及RTT通道，不依赖客户端ELF。项目变量观察仍以已有ELF为正常使用前提，不额外增加“无ELF工程”主流程。现有网页保持独立可用；客户端原生RTT是另一条SDK采集路径，不是网页换一种呈现。是否以后改用服务端统一采集另行决定，当前不重写网页、不将缓存查询直接当作原生面板的数据源。

已实现网页快捷入口：用户输入短主机名robocon-r1-debug，生成http://robocon-r1-debug.local:8000，交给系统默认浏览器打开。已有.local或完整域名不重复补后缀，IP不补.local，完整HTTP(S)地址保留明确指定的协议和端口；网页端口缺省8000来自现有部署约定，可修改，不从远程探针Port字段推导。使用URL解析与系统打开API，不拼接shell命令，不绑定Chrome，不内嵌浏览器。名称无法解析时展示实际地址并允许改用IP，不自动改动服务器mDNS配置。

入口可位于独立“小工具”页，无项目时最近地址保存到软件data；从项目进入时主机取现有remote-jlink.json，网页协议/端口覆盖可放project.json的独立web配置，不重复保存主机。独立入口输入不自动修改当前项目。打开的是既有网页主页，不调用/start_rtt，不自动启动Logger；网页自身行为沿用现有实现。不承诺自动选中某个探针，后续如需深链接再增量适配服务端。

当前网页RTT数据接口以缓存索引取增量，缓存裁剪/清空可能改变索引语义；不作为本产品首版的无损采集通道。当前rtt_port配置不能单独证明对应Telnet端口有监听或可写。

当前远程串口转发存在默认波特率和按行接收行为，也未提供已确认的通用参数控制接口。1 Mbps标准验收针对本机COM，5 Mbps为本机实验功能；远程TCP连接只表示字节通道连通，不继承本地速率承诺。

后续服务能力接口建议版本化并返回：API版本、设备稳定身份、实际端口、连接/RTT状态、串口可配置参数和控制结果。客户端按能力显示按钮，没有能力时提供手动配置说明，不返回伪造成功。

远程变量与网页RTT按二选一使用：用户在网页停止RTT后启动客户端远程变量采集；反向切换时先停止客户端采集并释放SDK连接，再在网页启动RTT。保留观察布局，不自动结束外部进程，失败显示占用与重试说明。首版不承诺同时查看、时序对齐、自动交接或租约；TCP串口及参数控制暂不实现。

远程服务位于受信任局域网是当前使用假设；开放到公网、身份认证和加密另行设计，客户端不自动配置端口外网暴露。

### 12.2 安装流程

离线导入或下载指定包 → 校验来源/摘要/平台/API → 安全解压至新版本暂存目录 → 检查清单和入口 → 非硬件自检 → 将新版本目录标记为已安装 → 用户选择更新工程锁。

拒绝解压越界路径、绝对路径、目录联接/链接及不合规条目；设置包大小、解压总量和文件数上限，避免异常包消耗磁盘。校验未完成的目录不能进入可执行版本集合。

安装只增加版本，不覆盖运行中的目录。失败清理仅限已确认归属于本次安装的暂存目录。旧版本保留，回退修改版本选择并验证兼容；不要卸载所有旧版后再尝试新版本。

两个真实工具Release及GUI未运行时的离线锁定/切换/回退已有证据，见18节；纯净Windows仍待验。文档维护不触发发布。

### 12.3 构建打包

产品版本遵循REL-10及概要10.4，构建时注入各入口并校验一致性。产品版本、文档修订号和外部工具锁定版本分别管理；VERSION初始0.1.0-alpha.0只是开发基线，文档0.7不代表客户端已发布。

发布门统一采用需求第8节AC验收项，EXP-01单列实验报告。发布清单记录完整commit SHA和验证范围；验证不自动触发tag、Release或部署。

C#内部客户端使用dotnet publish Release/win-x64自包含产物，GUI/Worker/CLI共用运行时；外部交付采用.NET自包含单文件Portable入口，启用IncludeNativeLibrariesForSelfExtract和压缩，不Trim/AOT。内嵌ZIP与逐文件SHA256清单，准备锁避免并发解压，临时目录验证后原子改名为data/runtime/版本-摘要；每次启动校验受管文件，损坏拒绝执行。SDK/CLI进程隔离及独立Debug_LAN版本缓存保留。

### 18.3 采集与串口的软件结论

采集计划更新、会话代次、超时释放和过期值算法按第7～9节维护，不另留分批实现。离线覆盖含ELF半写/摘要变化、无效计划保留、地址溢出、重复身份、宽度检查、旧会话/旧代事件过滤及释放失败重试；实机采集中地址更新和RTT连续性仍待验。

真实Worker使用故意无效DLL验证装载失败、退出和新会话重试；未装载SEGGER库或连接设备。Worker按序列号/IP绑定外部DLL，设置InhibitConnectRetries，不主动发送烧录/复位/停核命令；实际设备行为仍须C-05。

观察准备与协调的职责见概要7.7。观察准备从MainWindow抽到Core，返回完整ObservationRequest及索引快照；本地不读取远程草稿，远程读取保存JSON并关闭本地RTT，仅RTT无需解析ELF。启动不再集中保存并解析串口输入。观察协调器串行操作，释放失败保留所有权，旧会话/旧代次与故障后的排队事件不进入新显示；串口控制器等待周期发送结束后释放独立会话。观察、远程预览和串口连接状态接入小范围绑定，编辑远程参数、目标或工具选版后必须重新预览。

绘图移至独立控件，限制16条/每条2000点，像素桶保留极值，同快照/尺寸复用冻结几何；数值通知与RTT全文更新按变化触发，隐藏页仍消费数据但跳过展示。观察和串口各轮最多256项或8ms。保留现有采样/工作进程协议、配置字段及点序号横轴，没有替换绘图库或增加设备能力。

串口显示及恢复遵循第10节。SerialTextBuffer保留有界方向片段和不可变快照；SerialLogView使用原生富文本按偏移增量更新，不插入[RX]/[TX]，复制不带隐式段落换行。冻结当前并分栏保留右侧快照、选区和模式，左侧继续接收；清屏只清实时侧，继续显示不重放、不清空实时历史。打开失败和同次运行内重开保留历史，关闭期间保持按钮锁定，排出已接受尾部后才允许新会话；切页不丢显示，编码切换不污染冻结快照或新解码器。周期反馈区分运行、停止中、已停止及故障，HEX错误中文化并保留异常详情。

工程解析成功重新计算ELF文件告警；观察准备失败保留当前目标已经验证的保存设置和已完成索引，缺远程配置显示保存身份及未解析状态，缺SDK显示真实已解析变量，均保持采集禁用；RTT关闭不再显示等待输出。未改变工作进程、固件或原始记录协议。这些功能属于0.3.0-alpha.0；最终本地包见18.5，尚未发布该版本。
