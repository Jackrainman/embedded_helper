# Embedded Helper

**🛠️ 给战队模板配一个 N 合一调试小助手。**

看变量、盯波形、读 RTT、发串口，再给工程接上远程调试——这些事，尽量在一个窗口里搞定。Embedded Helper 是一款配合 **VS Code + EIDE** 使用的 Windows 嵌入式调试助手，把工程配置、变量可视化、日志和串口工具放到一起。代码编辑、构建和源码调试仍由 VS Code/EIDE 完成。

我想做的是 **N 合一**：围绕战队日常调试，把常用工具和工程配置串起来。目前主要适配战队模板，先把这条使用路径做好，再逐步扩展适配范围。

> 当前按开发内测版本交付。不同模板、硬件链路和 Windows 环境的验证状态以对应 Release 说明为准，软件检查通过不代表全部实机验收已完成。

## 功能概览

- **工程读取**：打开 EIDE 工程目录或 `.code-workspace`，识别工程、构建目标、MCU 和 ELF/AXF。
- **变量可视化**：搜索并添加变量，勾选想看的曲线，查看实时数值，调整请求采样率，导出完整记录为 Excel。
- **RTT 监视**：本地读取 RTT Up 通道 0；远程 RTT 打开既有网页。
- **串口助手**：独立使用本地 COM 口，支持文本/HEX 收发、周期发送、冻结分栏和双向原始记录。
- **远程接入**：从 LAN_Debug Release 在线或离线导入客户端脚本，生成工程连接配置和 VS Code 任务。
- **设置与诊断**：查找或指定 J-Link、ELF 解析工具，检查配置并打开日志目录。

### 已经有 MCUViewer，为什么还做这个？

[MCUViewer](https://mcuviewer.com/) 已经提供变量绘图、SWO 跟踪和高速记录，并支持多种探针和平台。Embedded Helper 的优化重点放在**战队工程的整套调试流程**：从打开模板工程，到看变量、读日志、用串口，再到接入 LAN_Debug，减少来回切工具、重复找文件和配置路径的操作。

| 战队调试时常做的事 | Embedded Helper 提供的便利 |
| --- | --- |
| 打开模板，找到当前目标和固件 | 读取 EIDE 工程与 `.code-workspace`，识别 MCU、构建目标和 ELF/AXF；选好目录就直接打开 |
| 看完曲线，还要查日志、发串口 | 变量曲线、本地 RTT、独立串口助手集中在同一个客户端；变量和 RTT 共用工程连接配置 |
| 给现有工程加远程烧录、调试入口 | 导入 LAN_Debug 官方客户端脚本，配置连接参数并生成 VS Code 任务；日常仍在熟悉的 EIDE 中构建 |
| 调试时只盯住几个关键变量 | 每个变量可单独勾选显示，隐藏曲线仍继续采集和记录；默认统一坐标，需要时再开分道缩放 |
| 下次接着调，或者把工程交给队友 | 变量列表、采样率和共享连接随工程保存；完整采集记录可导出 Excel，方便复盘 |

这些优势主要体现在**模板适配和工具整合**。目前本地采集以 J-Link 为主，也没有完成与 MCUViewer 的采样性能对比；需要 SWO、高速记录或更广的探针支持时，可以结合 MCUViewer 的官方功能说明选择工具。本项目界面中的“MCU Viewer”是变量观察页面名称。

## 使用前准备

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows x64；首批验证环境为 Windows 11 x64 |
| 运行客户端 | 使用发布版 EXE，无需另装 .NET、Python 或开发 SDK |
| 本地变量与 RTT | SEGGER J-Link 软件、对应驱动、J-Link 探针和目标板 |
| ELF 变量解析 | 内置解析可直接使用；部分 ELF 需要 ARM GNU 工具链中的 `arm-none-eabi-readelf.exe` |
| 执行远程烧录/调试任务 | 开发电脑安装 Python 3.10+ 和 SEGGER J-Link；远端 LAN_Debug 服务可用 |
| 串口助手 | 本地 COM 设备及驱动；不需要打开工程或连接 J-Link |

目前主要适配战队使用的 G4、H7、F4、F1 FreeRTOS 模板。其他工程能否直接使用，取决于 EIDE 配置和固件格式；已完成配置样本适配不等于所有系列均已实机验证，F1 裸机不在当前范围内。

## 下载与启动

1. 打开 [Releases](https://github.com/Jackrainman/embedded_helper/releases)，选择所需版本。
2. 下载 `EmbeddedHelper.exe`，或下载 ZIP 后完整解压。**不要直接在 ZIP 内运行。**
3. 将 EXE 放在一个可写目录中，双击启动。
4. 首次启动会在 EXE 旁创建 `data`，并在 `data/runtime` 准备内部组件，无需手动管理 DLL。

找个普通可写目录放好就能开始，不必额外安装开发 SDK；尽量避开需要管理员权限才能写入的位置。

### 升级与迁移

- **升级**：关闭软件后替换 `EmbeddedHelper.exe`，保留原有 `data`。
- **迁移**：将 EXE 和整个 `data` 一起复制到新位置。
- **不要删除整个 `data`**：其中包含本机设置、工具缓存、日志和串口记录。
- 工程配置仍保存在原工程中，不会复制业务工程。

## 快速开始：观察本地变量

### 1. 打开工程

1. 进入 **工程 → 工程概览**。
2. 点击 **打开工程**，选择目录后立即打开；也可以在输入框中填写工程目录或 `.code-workspace` 路径后按 Enter 打开。
3. 在 **构建目标** 中选择要使用的目标。
4. 检查页面显示的 MCU、固件符号文件和配置来源。

选错目录也不用担心：取消选择会保留当前工程。

打开工程只读取配置，**不会自动构建、烧录、复位或连接设备**。再次启动软件时会尝试恢复上次工程，但同样不会自动开始采集。

### 2. 准备本机工具

进入 **设置与诊断 → 采集与解析环境**：

1. 在 **J-Link 软件组件（DLL）** 下点击 **自动查找**；有多个候选时选择需要使用的版本，也可以点击 **手动选择文件** 指定 `JLink_x64.dll`。
2. 如果 ELF 解析提示需要外部工具，在 **ELF 变量解析组件** 下自动查找或手动选择 `arm-none-eabi-readelf.exe`。
3. 点击 **检查配置** 查看结果；需要排查时点击 **打开日志目录**。

文件校验通过只表示路径和文件格式有效，不代表设备已经连接。实际加载和连接会在开始采集时验证。

### 3. 解析 ELF/AXF

1. 回到 **工程 → 工程概览**。
2. 优先使用自动识别的固件符号文件；需要查看其他文件时，点击 **选择 ELF/AXF**。
3. 点击 **解析变量**，确认解析成功。

请选择与目标板当前固件匹配的 ELF/AXF。手动选择的外部文件只用于本次查看，不会被复制或修改。ELF 重新构建后，软件会提醒更新；文件时间变化本身不能证明新固件已经烧录。

### 4. 保存本地连接

1. 确认窗口顶部连接方式为 **本地**。
2. 点击右上角 **连接配置**。
3. 点击 **刷新探针**，选择目标 J-Link；多个探针按序列号区分。
4. 点击 **保存共享连接**。

顶部绿色状态表示配置有效，不表示已经连接或正在采集。软件不会在原探针离线时自动改连另一个探针。

### 5. 添加变量并开始采集

1. 进入 **MCU Viewer**。
2. 点击 **添加变量**，按名称、完整成员路径或类型搜索，再点击结果旁的 **添加**。最多添加 64 项。
3. 在 **频率设置（Hz）** 中输入请求频率，按 Enter 或让输入框失去焦点后保存。
4. 点击 **开始采集**，查看当前值、曲线、实际接收率和数据缺口。
5. 用变量旁的 **显示** 勾选框决定右侧画哪些曲线；新变量默认勾选，取消勾选仍继续采集、更新数值和记录数据。
6. 需要冻结画面时勾选 **暂停显示**；这只暂停曲线和数值显示，后台采集与记录仍继续。暂停时也能隐藏或恢复已有曲线，显示的仍是暂停时的快照。
7. 结束后点击 **停止并释放**。

变量列表和频率保存在工程中。曲线显示勾选仅用于当前打开的工程，不写入工程配置。采集中可以勾选或取消曲线显示；添加、移除变量或修改频率前，请先停止采集。

### 6. 导出调试数据

停止采集后点击 **保存调试数据**，将本次会话的全部已接收批次导出为 `.xlsx`。导出包含时间、完整变量名和缺失批次，不受曲线仅显示最近 2000 点的限制。空记录或写入失败时会提示，可保留记录后重试。

## 各页面使用方法

### 工程

- **工程概览**：打开工程、切换构建目标、选择并解析 ELF/AXF、查看配置诊断和最近工程。
- **远程配置**：维护服务器、远程探针端口、网页地址，以及 LAN_Debug 工程接入。
- **连接配置**：从窗口右上角进入，保存 MCU Viewer 与 RTT 共用的本地探针或远程连接。
- 顶部 **本地/远程** 只切换可视化连接方式，不会自动连接，也不会改变 EIDE 烧录方式。

### MCU Viewer

- 支持固定地址的全局/静态标量，以及嵌套结构体、定长数组中的基础数值成员。
- 支持有符号/无符号 8、16、32 位整数和 `float32`。
- 长名称会省略中间路径，鼠标悬停可查看完整名称、类型和地址。
- 曲线按变量列表顺序显示已勾选且有数据的前 16 项，每项保留最近 2000 个显示点；隐藏前面的变量后，后面的曲线可补入。
- **分道独立缩放默认关闭**，方便在统一坐标下比较数值；勾选显示的变量不超过两个时，可以手动开启。超过两个时自动恢复统一坐标。
- 请求频率不等于实际采样率，也不代表固件端精确同步采样。

### RTT 监视

**本地 RTT：**

1. 打开工程并保存本地共享连接，无需解析 ELF 或添加变量。
2. 进入 **RTT 监视**，点击 **开始本地 RTT**。
3. 查看 RTT Up 通道 0 的日志；需要时点击 **清屏**。
4. 结束后点击 **停止并释放**。

**远程 RTT：**

1. 在 **工程 → 远程配置** 中保存服务器和网页地址，并将顶部连接方式切为 **远程**。
2. 进入 **RTT 监视**，点击 **打开远程 RTT 网页**。
3. 日志显示和停止操作均在网页中完成。

MCU Viewer 与 RTT 共用采集连接，切换前先在当前页面点击 **停止并释放**。远程变量与网页 RTT 也必须手动二选一：开始远程变量采集前停止网页 RTT；返回网页 RTT 前停止 MCU Viewer。使用其他烧录或调试工具前，同样先释放 J-Link。

### 串口助手

串口助手无需打开工程，可独立使用：

1. 进入 **串口助手**，点击 **刷新端口** 并选择 COM 口。
2. 设置波特率、数据位、校验、停止位和流控。
3. 需要保存记录时勾选 **保存双向原始记录**，再点击 **打开串口**。该选项在打开时应用，修改后需重新打开串口。
4. 在发送区输入内容，选择是否使用 **HEX 发送** 以及 **不加换行 / LF / CRLF**，点击 **发送**。
5. 需要重复发送时填写 **周期 ms**，点击 **周期发送**；点击 **取消周期** 停止。
6. 点击 **关闭串口** 释放端口。

显示与记录说明：

- 接收和发送使用不同颜色；发送记录独占一行，实际末尾换行显示为 `(LF)` 或 `(CRLF)`。
- 显示中的分行和标签不会增加发送字节，也不会修改原始记录。
- **冻结当前并分栏** 后，左侧继续更新，右侧保留快照；**继续显示** 返回单栏，**清屏** 只清实时侧。
- 切换文本编码或 HEX 显示会重置实时显示，不影响历史快照和原始记录。
- **最近发送** 最多保留 20 项；点击 **打开记录目录** 查看原始记录。
- 标准支持范围最高 1 Mbps；5 Mbps 为实验档，取决于转接器、驱动和线路。
- RS485 仅支持转接器硬件自动换向；TCP 远程串口暂不支持。

串口与 J-Link 生命周期相互独立，停止变量或 RTT 采集不会自动关闭串口。

## 配置 LAN_Debug 远程接入

远程接入用于在现有工程中添加连接配置、VS Code 远程烧录/调试任务及配套脚本。操作前应准备可用的 LAN_Debug 服务端、服务器地址和远程探针端口。

### 在线导入

1. 打开工程并选择构建目标，进入 **工程 → 远程配置**。
2. 填写 **服务器主机名 / IP**、**远程探针端口**；按需填写 **网页地址** 和 **本机 GDB 端口**。
3. 选择 LAN_Debug 客户端版本，点击 **一键导入 LAN_Debug**。
4. 检查修改预览、工具状态和页面结果。
5. 在 VS Code 的任务列表中选择已导入的远程烧录或 LAN 调试任务。

默认会将 EIDE 上传方式切换为 Custom CLI 并写入烧录命令。若要保留当前烧录配置，在导入前勾选 **不替换 Custom CLI 烧录选项**。

### 离线导入

1. 从 LAN_Debug Release 获取官方客户端 ZIP；不要重新打包或修改包内容。
2. 在 **远程配置** 中点击 **从 ZIP 导入并接入**。
3. 选择 `LAN_Debug_client-*.zip`，检查应用结果。

也可以在 **设置与诊断 → LAN_Debug 工具管理** 中预先下载、校验或导入工具缓存，再返回工程页完成接入。

### 仅修改连接参数

点击 **仅预览连接参数**，检查修改内容后点击 **应用已预览的修改**。需要同时更新脚本和任务时使用 **预览接入修改** 或一键导入。

### 注意事项

- 导入、保存和移除只修改配置，**不会自动烧录或开始调试**。
- 已有本地任务和用户配置会保留；发现冲突时停止并提示，不强行覆盖。
- 旧 `Debug_LAN` 配置可继续读取；显式重新导入时才迁移由助手管理的旧入口。
- **预览移除接入** 只计划移除受管内容；远程 JSON、工具锁和缓存会保留供复用。
- 写入中断时可使用 **恢复未完成写入**；确认保留当前状态时选择 **保留现状并结案…**。
- 工程脚本可随工程提交；另一台电脑仍需准备 Python 3.10+ 和 SEGGER J-Link。

## 数据与配置位置

| 内容 | 位置 |
| --- | --- |
| 本机设置、工具缓存、内部运行组件 | EXE 旁的 `data/` |
| 应用日志 | `data/logs/` |
| 串口双向原始记录 | `data/serial/records/` |
| 工程变量列表与采样率 | 工程内 `.embedded_helper/watch.json` |
| 工程共享连接配置 | 工程内 `.embedded_helper/connection.json` |
| 远程连接参数 | 工程内 `LAN_Debug/remote-jlink.json`；兼容既有旧位置 |
| VS Code 任务与调试配置 | 工程内 `.vscode/` |

原始串口记录的顺序表示上位机观察顺序，不证明对端已经收到数据，也不证明跨方向的物理发生顺序。

## 常见问题

### 找不到 J-Link 或无法开始采集

在 **设置与诊断** 重新选择有效的 `JLink_x64.dll`，再到 **连接配置** 刷新并选择在线探针。确认目标板供电、USB 和驱动正常，且其他调试工具没有占用探针。失败后按页面提示重试，不会自动切换到其他探针。

### ELF 解析失败或变量找不到

确认 ELF/AXF 与当前构建目标匹配且文件可读取。若提示需要外部解析工具，在 **设置与诊断** 配置 `arm-none-eabi-readelf.exe`。局部变量、任意表达式和不受支持的类型不能按普通固定地址变量添加。

### 提示探针被占用

先在 MCU Viewer 或 RTT 监视中点击 **停止并释放**，再关闭其他正在使用 J-Link 的烧录/调试工具。远程网页 RTT 需要在网页中手动停止。

### 远程配置有效但无法采集

配置有效不代表网络、远端探针或目标已经连接。检查服务器地址、远程探针端口和 LAN_Debug 服务；网页端口与远程探针端口不是同一个配置项。

### 串口打不开或发送失败

确认 COM 口未被其他程序占用，参数与设备一致，并查看连接状态和 **串口详细诊断**。发送计数表示驱动接受的数据量，不等于对端已成功处理。

### 升级后想保留设置

只替换 EXE，不要删除 `data`。迁移到另一台电脑时同时携带 `data`；工程内的 `.embedded_helper`、远程配置和 VS Code 文件随工程一起迁移。

## 当前限制

- 不支持位域、匿名成员、联合体、指针跟随和 64 位数值采集。
- 不提供 HSS 高速采样、任意表达式求值或完整源码调试器。
- 本地 RTT 当前读取 Up 通道 0；远程 RTT 依赖网页。
- 变量与 RTT 不能同时占用采集连接，需停止后手动切换。
- 不支持 TCP 远程串口；NRF 链路在电脑端按普通 COM 使用。
- 远程烧录/调试与可视化连接方式相互独立，切换顶部连接不会修改 EIDE 上传方式。
- 硬件、纯净 Windows 和各模板实测范围以 Release 说明为准。

## 开发与验证

日常使用不需要以下环境；它们仅用于源码开发和打包：

- Git、Python 3.12+（仅标准库 Harness，无 pip 依赖）
- `global.json` 锁定的 .NET SDK **10.0.403**
- C# / WPF，Windows x64 自包含发布

```bash
# 首次克隆后安装提交钩子
python scripts/verify.py --install-hooks

# 仓库文档、边界和 Harness 检查；不构建客户端
python scripts/verify.py

# 只检查客户端工程和精确 SDK 是否就绪
python scripts/verify.py --client-preflight

# 锁定恢复、格式检查、Release 构建和 C# 测试
python scripts/verify.py --client

# 从干净已提交基线打包并运行同包 GUI/CLI 自检
python scripts/package_client.py
```

打包产物默认位于 `dist/candidate/`。仅软件逻辑通过不等于 GUI、硬件或发布验收通过；具体范围见对应清单和 Release 说明。
