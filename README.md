## 当前范围

Windows本地小助手配合VS Code/EIDE使用。第一版围绕现有模板工程的可选远程接入、统一本地/远程变量与RTT可视化、独立串口助手。默认本地连接，串口助手不依赖项目。

首版交付底线：G4完成实测，H7/F4/F1 FreeRTOS完成移植与配置样本检查；F1裸机不在范围。串口标准到1 Mbps，以同时双向连续30分钟验收，5 Mbps作为实验功能公测，不阻塞发布。ELF文件更新仅提醒，用户手动更新变量地址；采集与源码调试通过停止/开始手动切换，故障重试前先清理旧连接。

工程配置统一放在.embedded_helper，可提交仓库；含接入条目记录，便于队友继续使用或移除LAN接入。首版只维护一个当前构建目标。产品版本参考TeamHub，使用根VERSION和统一更新脚本；GUI/CLI/采集进程同版，外部Debug_LAN依赖单独锁定。

采用便携软件布局，在软件目录下创建data文件夹保存本机设置、工具缓存、串口历史、日志及事务备份。每个项目的数据仍保存于自身项目目录，EIDE本地/远程上传配置保留在原.eide文件，小助手项目状态保存在.embedded_helper；切换项目不覆盖其他项目数据。

“开始调车”场景封装、从最新稳定模板新建工程、远程串口控制及统一记录回放按文档中的优先级逐步评估。已有业务工程自动模板升级不纳入当前范围。

## 维护基线

一站式先统一入口与项目上下文。已有LAN-Debug-Server网页RTT保持独立可用；候选“小工具”入口可将robocon-r1-debug补全为http://robocon-r1-debug.local:8000并用系统默认浏览器打开，无需捆绑Chrome。该入口与客户端原生RTT是两种不同方案，不据此要求重写网页；原生RTT取舍与后续统一接口另行收敛。

选中同一项目目录直接读回原配置，不创建项目副本；服务器修改写回该项目现有remote-jlink.json。当前优先兼容旧配置、脚本与任务，打开工程不强制迁移；以后确需淘汰旧实现时，再同步修改并验证上下游。

- 现有Debug_LAN暂以STM32-Template为单一源码上游，先尝试Release分发；小助手与具体工程引用工具版本，避免复制脚本后独立修改。
- 模板适配集中在一个模块；GUI、CLI和任务使用统一配置及版本规则。工程真实文件仍是相应配置的输入。
- 工具兼容修复可以独立更新；协议变化、配置语义变化和模板结构变化仍需明确适配与迁移。
- Python/C#尚未定案；先用G4连接与发布原型确定实现。1 Mbps需标准验收，5 Mbps性能留待公测。

## 后续更新规则

需求变更先更新需求编号和验收条件，再同步模块职责、详细接口及样本。新增GUI可改字段时，检查读取、校验、变更计划、写入、撤销、CLI消费和旧版本迁移，避免只新增界面控件。

新增模板/硬件区分已移植、实机已验证和实验功能，不凭相似目录或驱动接受参数宣布实测通过。接口冻结后记录版本和兼容规则；重大决策在概要设计的ADR表保留依据。

建议从M0工具版本分发试验开始，再验证G4配置适配与SDK采集原型。当前文档中的“拟新增”“候选”“待验证”均不能当作已完成能力。
