# Embedded Helper 设计文档

文档版本0.15，2026-10-18。已建立C#、WPF和.NET 10客户端，提供工程读取、ELF标量索引、变量/RTT采集入口、远程JSON维护、独立串口、设置与诊断。Windows x64自包含单EXE按开发内测交付；硬件验收由用户后续执行，不宣称完整P0通过。

## 当前范围

Windows本地小助手配合VS Code/EIDE使用。第一版围绕现有模板工程的可选远程接入、本地/远程变量可视化、本地原生RTT及独立串口助手。远程变量与既有网页RTT二选一、手动切换；NRF按本地COM，TCP串口暂不做；串口记录由上位机保证顺序，时间戳可选。

功能优先级以需求第4节为准，发布通过条件以第8节AC验收项为准。开发待验证问题统一见需求第9节，不要求用户逐项决策后才开工。

## 维护基线

需求与验收统一维护在需求说明书；概要设计维护模块职责和架构决策；详细设计维护数据模型、算法和测试步骤。下游文档引用需求编号，不重复制定功能范围或发布门槛。用例、实现方案和验收步骤是不同层次的描述，不因涉及同一功能就删除。

配置归属见概要第6节，旧工具兼容见REM-07及详细设计第6节，网页快捷入口规则见详细设计第11节，产品版本纪律见REL-10及概要10.4。首批范围见需求4.1；开发内测按AC-14，完整验收按AC-13，不代表全部P0已完成。

## 后续更新规则

需求变更先更新需求编号和验收条件，再同步模块职责、详细接口及样本。新增GUI可改字段时，检查读取、校验、变更计划、写入、撤销、CLI消费和旧版本迁移，避免只新增界面控件。

新增模板/硬件区分已移植、实机已验证和实验功能，不凭相似目录或驱动接受参数宣布实测通过。接口冻结后记录版本和兼容规则；重大决策在概要设计的ADR表保留依据。

G4一键VS Code接入/共享移除及两个已发布工具版本的下载、离线导入、锁定和回退已可用。H7/F4/F1已通过配置样本移植；可选EIDE上传切换、官方工具清单刷新与网页切换前停止采集已实现。硬件与完整P0验收仍待用户执行。文档中的“拟新增”“候选”“待验证”均不能当作已完成能力。

开发采用关键风险原型验证、小批次迭代交付、稳定版本补丁维护的节奏；集中功能变更留到下一轮更新，详见概要14.1。

## 开发与验证

标准库Python Harness仅用于开发与打包，不进入客户端运行依赖；产品及其测试采用C#。提交、验证及设备操作边界见根AGENTS；推送、打标签与发布按具体任务授权执行。

统一入口：`python scripts/verify.py`，只运行仓库检查与Harness测试，无pip依赖、不构建、不访问设备。首次克隆运行 `python scripts/verify.py --install-hooks`；提交门仍验证索引快照。开发需要Python 3.12+、Git；客户端开发另需global.json指定的SDK。

`python scripts/verify.py --client-preflight`检查客户端工程和精确SDK，不构建；缺少时返回2。`--client`执行锁定恢复、格式检查、Release构建及C#测试；加`--configuration Debug`验证Debug布局，Worker由测试构建自动准备，不依赖Release目录。`python scripts/package_client.py`从干净已提交基线构建ZIP、解压后运行真实GUI/CLI自检并生成同包证据，产物在dist/candidate。旧Qt入口已退出。活动任务见[唯一账本](.harness/todo.json)，证据见详细设计18节。

源码构建后的离线GUI验证使用 `python -X utf8 scripts/gui_smoke.py`；支持 `--configuration Debug`、`--app-dir <已有WPF构建目录>`、`--timeout <秒>`，不会自动构建。入口按脚本位置定位仓库，可从其他工作目录启动。样本复制至tmp隔离副本，不复制既有data；结果、日志和20张截图归test-results/gui-smoke，每配置自动保留最近一次成功证据，失败证据保留待排查。成功删除运行副本，失败保留现场；`--keep-workspace`可显式保留成功副本。

本地产物保留和清理规则见根AGENTS。已保留的历史完整候选集中在`dist/candidates/版本-提交短SHA/`，同版本不同字节以用途后缀区分；旧临时验证材料集中在test-results/legacy，本次维护摘要见详细设计18.20～18.22。既有候选保持原源码/SDK绑定，本轮源码验证不替代重新打包验收。

## 启动、产物与发布

直接交付 `EmbeddedHelper.exe`，另提供同字节EXE的可选ZIP、清单及摘要。将EXE放在可写目录并双击，无需Python或预装.NET；J-Link软件和设备驱动由用户安装。DWARF4内置解析，DWARF5调用已有ARM readelf（自动定位EIDE工具链，亦可在设置中填写）。软件在自身目录创建data；升级保留data，工程观察设置保存到.embedded_helper/watch.json。

[Windows工作流](.github/workflows/verify.yml)运行仓库及客户端门。[内测发布工作流](.github/workflows/release.yml)核对候选运行来源和同包证据后上传原包；发布输入由[scripts/release_gate.py](scripts/release_gate.py)检查。用户授权先发布离线开发内测：developer-preview只接受软件门真实通过，并强制列明硬件与纯净Windows未验证；完整验收仍保留tested-prerelease门，契约见详细12.4。仓库管理员权限已核实，远端运行结果随批次记录，分支保护未配置。

已发布的开发内测版本：[0.2.0-alpha.8](https://github.com/Jackrainman/embedded_helper/releases/tag/v0.2.0-alpha.8)，[直接下载单EXE](https://github.com/Jackrainman/embedded_helper/releases/download/v0.2.0-alpha.8/EmbeddedHelper.exe)，约98MiB。该版本补齐串口软件流程、采集计划更新、工具版本管理和G4 VS Code接入；发送编码、历史及显示窗口可用，实物链路仍按C-05验收。

当前开发版本为0.2.1-alpha.3，已提取观察准备快照、采集协调与独立绘图控件，观察/远程/串口关键状态采用绑定，串口会话与周期发送独立协调；源码构建与离线GUI验证见详细设计18.23。18.16的单EXE候选属于旧版本，本轮未重新打包或发布。

远程接入：先在设置页下载/导入 Debug_LAN，并点击绑定本机VS Code入口；完全退出并重新打开VS Code使用户环境变量生效。新接入使用EMBEDDED_HELPER_ENTRY指向外层EXE，通过--cli进入当前组件。旧工程须在远程配置页预览并应用以迁移命令；旧EMBEDDED_HELPER_HOME不被覆盖，尚未迁移的工程仍依赖旧组件目录，全部迁移前不要删除该目录。更换或回退工具版本后再次预览应用；项目只保存精确版本锁及稳定入口引用。移除使用工程内归属记录，不依赖本机旧备份；远程JSON和工具锁保留供旧入口/后续复用。

单EXE首次启动自动将内部运行组件准备到旁边data/runtime，设置仍在data/settings；搬迁时携带data保留配置，更新只替换主EXE。内部SDK工作进程和CLI保持隔离，用户无需管理DLL。运行时可能另用Windows临时缓存。

串口打开/关闭合并为单按钮，绿灯表示驱动连接正常，红灯表示未连接或故障，附带文字；切换期间禁用重复操作。程序图标和页首logo使用用户提供的原图。

紧凑专业界面采用工程、查看变量、串口助手、设置与诊断四项导航。工程内含工程概览、观察设置与远程配置。先选择目标与 ELF，在观察设置中勾选变量、设置连接方式/采样率/本地 RTT并保存；查看变量页读取工程保存值，缺项提示补全。本机 DLL 与 readelf 路径在设置与诊断维护；串口独立使用。样式资源及原生GUI验证见详细设计18.18～18.19。
