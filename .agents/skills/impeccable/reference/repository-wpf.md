# Embedded Helper WPF adaptation

This repository uses WPF and its existing .docs specification/design documents as design authority. Read AGENTS.md and the affected implementation first. Missing PRODUCT.md/DESIGN.md is not missing product context; do not create those files, surface-brief trees or a second design system as a side effect.

Use Operate mode for the application: task completion, readable state, keyboard focus, consistent native interaction and reliable saving. A targeted fix does not require a product interview, visual-world replacement or a design menu. Resolve routine choices from the accepted requirements; ask only about consequential unresolved choices.

The generic context/init/new-work commands assume web/iOS/Android or their artifact formats. Do not run them as mandatory setup for this WPF repository. Use relevant critique/clarify/operate guidance as methods, adapting it to XAML; mobile-specific audit metrics and browser selectors do not become WPF acceptance criteria.

For user-task review, use the available user-task-review skill or the checks in the repository workflow: trace the real event/persistence paths and verify the target package. Source review is not UI execution evidence. Use the installed Computer Use skill for native Windows interaction, and the user-designated browser tool for web pages.

Record decisions in the existing design documents and tasks in todo.json. Build/version/package/test/cleanup follows .agents/workflows/change-test-deliver.md, not an independent design-skill release process. Fix real defects even if the generic stylistic iteration budget is exhausted.

No automatic changes to proxy/security settings, installed plugins or user workspaces are implied by a design request. Preserve original windows, close only task-created instances, and distinguish software simulation from device verification.
